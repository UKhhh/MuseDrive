## 能实现什么功能，以及怎么和 Muse 联动

### 1. 只读查询（已经验证能用）

你在聊天里用正常语言问，比如“电量多少”“胎压怎么样”，Muse 会先查 token、车睡着了先唤醒、再调 Fleet API、换算单位、用你的语言回答。这个模式不给车发任何命令。

- 电量和续航：电量、可用电量、额定续航（公里）、充电状态
- 充电：充电上限、充电电流设置、定时充电时间、充电口开没开、锁没锁好、上次充电加了多少度
- 位置和行驶状态：GPS 位置、朝向、挡位、速度、功率
- 上锁和车身状态：锁没锁、每个门、前后备箱、每个窗开没开、哨兵、代客、行车记录仪状态
- 胎压：四个胎压（bar）、推荐值、软硬报警、上次更新时间
- 空调：车内车外温度、设定温度、空调开没开、座椅和方向盘加热
- 车辆信息：总里程、软件版本、车型和配置、外观颜色、轮毂、辅助驾驶硬件、充电口类型
- 显示设置：24 小时制、公里/小时、摄氏度、Bar、额定续航显示

### 2. 签名命令

你在聊天里用正常语言说，比如“闪一下灯”“开锁然后再锁上”，Muse 会先查车是不是停好的，敏感命令会先请你确认，再用 `tesla-control` 发签名命令，做完再查一次最终状态才告诉你完成了。

- **已验证能用的：** 闪灯、开锁、关锁（开锁再关锁那次最后验过是锁好的、门都关着）
- **工具里有、还没测的：** 鸣笛、空调开关和调温、前后备箱、远程启动、哨兵、媒体、充电口
- **充电类，要先重授权：** 改上限、改电流、开始、停止、定时充电，旧 token 不会自动加权限，要先用带 `vehicle_charging_cmds` 的新授权换 token，而且每次改充电也要你单独确认

### 3. Muse 是怎么联动的

Muse 是聊天入口和定时器，不是特斯拉 App 的替代品：

- **聊天控制：** 你就在现在这个聊天里用中文说，Muse 把你的话翻译成接口查询或签名命令，英里换算成公里、时间换算成北京时间再报给你。
- **安全门：** 闪灯这种低风险的按你要求就做，开锁、远程启动、开后备箱、改充电这种敏感的，必须你每次单独确认，而且先查车是不是停好的，做完再查一次最终状态。
- **定时联动（可以做、默认没开）：** 因为 Muse 能跑定时任务，可以把车的数据和你别的信息拼起来，比如早上报告（天气 + 电量 + 续航 + 胎压）、低电量低胎压提醒、周末出行前续航检查、停车场找车（闪灯 + 鸣笛）、出发前预冷预热、充电完成通知。这些都要你单独批了时间表才开，没有分钟级轮询。
- **私人定制早报 / 简报（可选，这个项目里最有用的联动）：** 每天早上你定的一个时间，Muse 只唤醒车一次，一次性拿电量、续航、充电、胎压、上锁状态、位置，再拼上车所在地的当天天气，给你一份短的、带用车建议的早报，不是只报一堆数字。比如：今天续航够不够你计划的行程、晚上要不要充电（23:00 的定时充电是不是已经设好了）、出发前胎要不要打气、车锁好没有、哨兵开没开。你可以自己定早报里放什么（比如工作日通勤还是周末自驾、平时几点出发、你习惯的充电上限），哪部分不想要就关掉。每天只跑一次，不是一直轮询，所以只花一次唤醒加几次数据查询的钱。
- **天气联动的胎压提醒（可选，在早报之外再加一层）：** 气温降了胎压也会降，大概每降 10°C、冷胎胎压会掉约 0.1 bar，所以突然大降温时，本来就偏低的胎很容易进一步低于推荐值，不一定是漏气。Muse 看到预报有大幅降温时（比如一夜降 8–10°C 以上，或者早上温度比昨天低很多），就查一次胎压（一次唤醒、一次 vehicle_state 查询），只有胎低于推荐值、或者有胎压软硬报警时才提醒你。提醒会说清是哪个胎、现在多少、推荐多少（比如 2.75 bar 对 2.9 bar）、冷胎要在开车前量、要尽快打气、在打气之前别高速跑长途。胎压正常的话就不提醒，正常冷天不会打扰你。这个提醒也要你单独批、阈值你自己定，不会每小时跑、也不会一直追踪车。
- **不做的事：** 不代替特斯拉 App、不在开车时控车、不实时连续追踪、不控别人的车。

## 开始之前 — 准备工作清单

缺一样，后面就会卡住，没准备好别从第一步开始。

1. **特斯拉车主账号**：必须是已经绑了这辆车的车主号，非车主授权不了、配对不了；双重验证要开着，手机上要有特斯拉 App，后面配对要用。
2. **GitHub 账号**：用来放公钥和回调页、开 Pages；双重验证要开着，恢复码离线存好；免费账号的话，公钥和回调仓库必须公开，私密仓库发不了 Pages。
3. **一个你能控制的公开域名**：GitHub 用户站域名就行，或者你自己的 HTTPS 域名，特斯拉要能不登录就抓到公钥，回调页也要普通浏览器能打开。
4. **一台能跑命令的机器**：AI 助手的云电脑就行，或者你自己的 Mac / Linux / Windows，要有 curl、Go、能 600 权限存私钥和 token 的地方，手机单独做不了这步。
5. **一个本地浏览器**：你自己手机或电脑上的 Safari / Chrome，用来走 OAuth，别用特斯拉 App 内置浏览器，也别用云浏览器，那步云浏览器会报错。
6. **不用先付费**：开始不需要绑付费方式，也不需要第三方订阅，但中国区收费见下面“费用”一节，目前页面列的是免费发现层且写着“临时”，所以用量先保持轻量。
7. **时间**：这不是一键配置，按顺序走开发者应用审批、密钥托管、合作伙伴注册、OAuth、车辆配对，OAuth 的 code 是一次性、短时有效的，可能要重拿一次。

## 怎么让本地的 AI 学会这个项目并开始执行

这是一个提醒，不是“一键安装”。一个新的 AI 光拿到这个仓库是控不了你的车的，它需要 skill、账号、还有你的授权，按这个顺序来：

1. **先把 skill 文件给 AI。** 把这个仓库克隆下来（或者只下载 `SKILL.md`），放到你那个 AI 加载 skill 的地方。Muse 的话就是 custom-skills 文件夹，其他 AI 工具就用它自己的 skill / 插件 / 指令文件夹，或者直接上传 `SKILL.md` 并告诉 AI“按这个当操作手册来”。千万别在对话里直接贴私钥、secret、token、车架号，skill 里写了 AI 只能从本地 600 权限文件里读这些。
2. **告诉 AI 从 Step 0 开始，别直接跳到 Step 4。** 你就这样说：“读 SKILL.md，从 Step 0 开发者账号注册开始，每一步需要我登录或确认的都先问我。”一个合格的 AI 会先对准备清单（特斯拉车主账号、GitHub 账号、公开域名、带 curl 和 Go 的机器、本地浏览器），缺一样就停下来问你，而不是直接去发命令。
3. **人必须自己做的部分，AI 做不了。** 特斯拉开发者门户登录和同意协议、GitHub 仓库和 Pages 搭建、本地浏览器里的 OAuth 登录和权限确认、特斯拉 App 里的虚拟钥匙配对，这些都得你自己做。AI 给你授权链接后，你要在本地浏览器里打开、确认应用名和权限、尽快把回调链接发回去，code 是一次性的、很快过期。
4. **让 AI 一步步验，别跳步。** 每个阶段做完 AI 都要先验证再往下走：应用显示有效、公钥链接返回 200 且内容对得上、合作伙伴注册返回 200、换 token 成功、查车列表能看到你的车、唤醒能用、只读查询能用、配对确认了、签名命令（比如闪灯）退出 0 且事后验过。哪一步失败就停在哪一步修，别跳到发命令。
5. **先确认你的 AI 到底能不能执行，不只是会聊天。** 如果你的本地 AI 没有终端、没有浏览器、没有安全的本地文件存储、没有定时任务，那它只能帮你写代码，查不了车、发不了签名命令、也发不了早报。这种情况你需要一个有这些能力的宿主（比如 Muse 的云电脑，或者你自己带后端的 Mac / Linux 机器），AI 只是跟你聊天的入口。
6. **早报这类自动化要最后再开。** 私人定制早报、天气联动胎压提醒都是基础跑通之后的自动化，不是 Step 0。等只读查询和至少一个签名命令都验过了，再单独批时间表和阈值。

## SKILL.md 大致做了哪些工作

`SKILL.md` 是 AI 助手帮你做这个项目时照着走的操作手册，里面没有你的 secret，也不会自己去控车。简单说，它做了这些工作：

1. **定什么时候用：** 查电量、续航、充电、胎压、位置、上锁状态、里程、空调、车辆配置；发闪灯、鸣笛、上锁、开锁、空调、前后备箱、远程启动、充电类命令；解释权限、诊断命令失败。别人的车、商业车队、没批过的权限，一律不做。
2. **定安全规则：** 敏感命令要确认、发改变状态的命令前要查停没停好、做完要再验最终状态、权限最小化、私钥、secret、token、code、车架号绝不公开。
3. **定中国区地址：** developer.tesla.cn、auth.tesla.cn、中国 Fleet API 主机和 audience，并提醒全球主机里查不到中国注册的应用。
4. **按顺序走 8 步（Step 0–7）：** 开发者账号注册、开发者应用、密钥对和公钥托管（GitHub Pages 只是一个举例，任何公开 HTTPS 托管都行，`.nojekyll` 只针对 GitHub Pages）、OAuth 之前的合作伙伴注册、本地浏览器 OAuth、token 刷新和轮换、只读查询（分号分隔端点、睡着先唤醒、胎压字段、英里换公里）、用 `tesla-control` 发签名命令（包括 Go 编译位置、REST 接口会 403 这个坑）。
5. **管 token 和加权限：** access 约 8 小时，refresh 约 3 个月且每次轮换，加权限要重新授权，旧 token 不会自动加权限。
6. **记踩过的坑：** 云浏览器 OAuth 会报错、网络丢包会烧掉一次性 code、逗号分隔端点会返回空、这台云电脑上 urllib 老断线要优先用 curl。
7. **管账号和费用：** Muse、特斯拉、GitHub 三个账号的安全清单（Apple ID 是单独的），以及 README“费用”一节里讲的成本，不经你同意不加付费方式。

## 这个项目包括什么

- 中国区开发者账号注册、开发者应用注册（developer.tesla.cn）、最小权限、应用审批
- EC 密钥对生成、公钥托管、OAuth 之前的合作伙伴注册。公钥用 GitHub Pages 托管只是一个举例，不是必须的 — 任何公开 HTTPS 托管都行（Cloudflare Pages、Netlify、Vercel、VPS 或家里服务器、其他你能控制的静态托管都行），只要特斯拉能不登录就从 `/.well-known/appspecific/com.tesla.3p.public-key.pem` 抓到公钥。GitHub Pages 要加 `.nojekyll` 这个要求只针对 GitHub Pages。
- 用户本地浏览器里的 OAuth、token 刷新和轮换、加权限后的重新授权
- 只读查询：电量、续航、充电状态、胎压、位置、上锁状态、里程、空调、车辆配置
- 用特斯拉官方 `tesla-control` 工具发的签名车辆命令（闪灯、鸣笛、上锁、开锁、空调、前后备箱、充电类命令需充电权限）

## 这个项目不做什么

- 不提供托管服务、服务器、也不提供能控制别人车的 App。
- 不包含、也绝不能包含任何私钥、client secret、token、授权 code、车架号、个人域名。
- 不保证特斯拉一定会批准、保留或继续支持任何开发者应用。

## 技能库说明

`skills/` 文件夹是一个可选的、可复用的技能合集。**它不是核心 MuseDrive 方法的必需部分，里面的技能也不会自动安装**：要先把 skill 文件复制到你自己的助手里，填好里面的定制表，第一次用之前先按自己的情况改好。

**这个库怎么维护：** 新技能由仓库所有者合并；别人想投稿就走 fork + Pull Request，或者开 Issue 让所有者审核。每个收录的技能都必须是通用的，不能含任何个人数据、token、密钥、车架号、账号信息，而且默认要是可选的、安全的。新技能上传时，要在下面的清单里按上传日期加一行，所以这个清单本身就是更新记录。

**目前收录（截至 2026-11-03，共 1 个）：**

- **2026-11-02 — 每日早报 / Daily Morning Briefing** — `skills/daily-morning-briefing/SKILL.md`（英文版）、`skills/daily-morning-briefing/SKILL.zh-CN.md`（中文版）。一份短的、温暖的、第一人称的早报，读起来像好朋友在说话，不是报告：当天天气和穿衣建议、只读的车辆状态（电量、续航、充电、胎压和推荐值对比、上锁状态、车内外温度）、昨晚睡眠和昨天活动（如果已同步）、以及自然融进对话里的个性化提醒；只有真正重要的紧急新闻才最多加一条。没有加粗的章节标题、没有数出来的建议清单、只给结论。车辆部分需要你自己的 MuseDrive 搭建；没有车的话，同一个 skill 也可以只跑天气加健康。
